! ---------------------------------------------------------------------------
! WHY YOUR OLD SELECTORS STOPPED WORKING
! ---------------------------------------------------------------------------
! Every selector in the original userstyle used data-testid, for example
!   div[data-testid="tweetText"], [data-testid="User-Name"],
!   article [role="group"], [data-testid="Tweet-User-Avatar"],
!   [data-testid="primaryColumn"], [data-testid="TopNavBar"],
!   .app-text-transition-container
!
! X shipped a new front end. On x.com today there is not one data-testid
! attribute left: a census of the profile, home, search, status, settings and
! messages pages finds 0. X's own stylesheet, styles-ZPhPmTLh.css, does not
! contain the string "data-testid" either. So all of the above match 0
! elements and the userstyle silently does nothing.
!
! The old class names are gone as well. X now uses a design system with
! x- prefixed classes (x-avatar, x-engagement-pill, x-middot-group), data-
! attributes (data-engagement-action, data-slot, data-icon), and plain
! Tailwind utility classes.
!
! That is why this list exists. It keeps your intent and targets the markup
! X actually serves now. Section 7 keeps the original data-testid rules as
! comments so you can see the mapping.
!
! A note on the two hidden-data-testid survivors: X still ships a handful of
! testids for a few small components (the toast viewport, the profile "Edit
! profile" button) and for embedded tweets. None of them are the timeline
! elements this list cares about, so they are not used here.
!
! ---------------------------------------------------------------------------
! WHICH ENGINE FEATURES ARE USED, AND WHY THEY ARE SAFE
! ---------------------------------------------------------------------------
! Brave's ad blocker is adblock-rust. The operators below are the ones Brave
! itself implements in
!   components/cosmetic_filters/resources/data/procedural_filters.ts
! They are :style(), :has(), :has-text(), :upward() and :matches-path().
!
! :has() is the important one. Your userstyle's feed rules needed
!   article:has(> div > div > a > [data-testid="Tweet-User-Avatar"])
! and the modern equivalent needs :has() too. Support for :has() landed in
! adblock-rust 0.6.3, so any Brave from 2023 on has it.
!
! :matches-path() replaces the url-prefix part of the userstyle, which used
!   @-moz-document url-prefix("https://x.com/home")
! A hostname-scoped adblock rule cannot carry a path, so path scoping is done
! with :matches-path() instead. It tests location.pathname + location.search.
!
! A caution that shapes every rule below: Brave turns a :style() body into
!   [attr][attr]{...your declarations...}
! and injects that as a stylesheet. Nested at-rules in that body DO work, as
! CSS nesting: @media { ... } inside the braces parses and applies, verified in
! Chromium. The rules below still keep to plain declarations, because none of
! them needs a media query; every effect wanted here is wanted at all widths.
!
! A second caution, and this one bit the original list. adblock-rust files a
! rule with NO action as a "hide selector". Brave then injects each hide
! selector as plain CSS:
!   selector { display: none !important; }
! That is fine for a real CSS selector, but ":has-text(Grok)" and ":upward(1)"
! are not CSS. The browser throws, Brave logs "ignored an invalid CSS
! injection" to the console, and the entry stays visible. So every rule below
! that uses a procedural operator carries an explicit
! ":style(display: none !important)" instead of relying on the implicit hide.
! The plain href and aria-label rules need no action and are left bare.
!
! A third caution, about testing. adblock-rust only splits procedural operators
! into the step list Brave executes when it is built with the css-validation
! feature, which Brave enables. A harness without that feature reports the
! whole selector as one opaque css-selector step, which no browser can run, and
! the list looks broken when it is fine. Check with css-validation on.
!
! A fourth caution, about href matching. Every route rule below is anchored to
! the relative form with href^="/..." rather than href*="/...". The substring
! form also matches absolute URLs, so a tweet that merely links to
! https://example.com/i/lists would lose its link. An earlier project of ours
! shipped that bug. All seven route rules here were confirmed to hide external
! links until they were anchored, and the test harness keeps those links as
! controls so the bug cannot come back.
!
! ---------------------------------------------------------------------------
! 1. TWEET TEXT - bigger, looser
! ---------------------------------------------------------------------------
! Was: div[data-testid="tweetText"] { font-size: 17px; line-height: 1.45; }
! X sets 15px/20px. The new text container is the dir="auto" block that wraps
! the tweet body. The span inside it inherits the size, but it also carries a
! text-[length:inherit] utility, so the size is set on the wrapper and the
! span is nudged as well for good measure.
x.com##article div[dir="auto"][class*="whitespace-pre-wrap"]:style(font-size: 17px !important; line-height: 1.45 !important;)
x.com##article div[class*="whitespace-pre-wrap"] span:style(font-size: inherit !important; line-height: inherit !important;)

! ---------------------------------------------------------------------------
! 2. DISPLAY NAME - bigger
! ---------------------------------------------------------------------------
! Was: [data-testid="User-Name"] { font-size: 16px; }
! X sets 15px on both the bold display name and the grey handle. Only the
! display name is enlarged, which is what the userstyle asked for.
x.com##article a[href] div[class*="font-bold"]:style(font-size: 16px !important; line-height: 1.35 !important;)

! ---------------------------------------------------------------------------
! 3. ACTION ROW - no fixed widths, even spacing
! ---------------------------------------------------------------------------
! Was: article [role="group"] { display: flex; justify-content: space-between;
!        padding-block: 10px; min-height: 52px; }
!      article [role="group"] > div { flex: 0 0 auto; width: auto;
!        min-width: 0; }
!      article [role="group"] svg { width: 20px; height: 20px; }
! The current action row is the div that holds the reply/repost/like/bookmark
! pills. It is identified by its children, which each carry
! data-engagement-action, rather than by its own Tailwind classes, so the rule
! survives a class rename.
!
! The child rule is the part that changes anything: X lays the pills out as
! equal-width columns (flex: 1 1 0%), so each pill is 115px and its icon floats
! in the middle of empty space. The userstyle asks for flex: 0 0 auto with
! width: auto, which makes each pill hug its own icon and count, and lets
! space-between do the spacing. That is the "no fixed widths, even spacing"
! the original comment describes.
x.com##article div:has(> [data-engagement-action]):style(display: flex !important; justify-content: space-between !important; align-items: center !important; padding-block: 10px !important; min-height: 52px !important;)
x.com##article div:has(> [data-engagement-action]) > div:style(flex: 0 0 auto !important; width: auto !important; min-width: 0 !important;)

! The icons, up from X's 18.75px.
x.com##article div:has(> [data-engagement-action]) svg:style(width: 20px !important; height: 20px !important;)

! Keep the little numbers on one line, at the userstyle's 13px.
x.com##article div:has(> [data-engagement-action]) [class*="tabular-nums"]:style(font-size: 13px !important; white-space: nowrap !important;)

! ---------------------------------------------------------------------------
! 4. STICKY HEADER - solid instead of see-through
! ---------------------------------------------------------------------------
! Was: [data-testid="TopNavBar"] { background: #000; backdrop-filter: none; }
! The header and the tab strip are the two sticky bars that blur what scrolls
! under them. Colour is left to X's own theme token, --x-bg-primary, which
! resolves to --x-white in light mode and --x-black in dark mode, so this
! stays correct in both themes. Only the translucency and the blur are
! removed; the bar becomes opaque and readable.
x.com##div[class*="backdrop-blur"][class*="sticky"]:style(background-color: var(--x-bg-primary, #000) !important; backdrop-filter: none !important; -webkit-backdrop-filter: none !important;)

! ---------------------------------------------------------------------------
! 5. HOME FEED - avatar beside the name, everything else full width
! ---------------------------------------------------------------------------
! Was, scoped with @-moz-document url-prefix("https://x.com/home"):
!   ... div:has(> div > [data-testid="Tweet-User-Avatar"]) {
!     display: grid; grid-template-columns: 38px minmax(0, 1fr);
!     column-gap: 12px; row-gap: 6px; align-items: start; }
!   ... > div:has(> [data-testid="Tweet-User-Avatar"]) { grid-column: 1;
!     grid-row: 1; align-self: center; }
!   ... > div:has(> [data-testid="Tweet-User-Avatar"]) + div {
!     display: contents; }
!   ... > div + div > :first-child { grid-column: 2; grid-row: 1;
!     align-self: center; }
!   ... > div + div > :not(:first-child) { grid-column: 1 / -1; min-width: 0; }
!
! The point of the style: the avatar and the name/handle share the top row,
! then the tweet text, media and buttons span the full width underneath.
!
! Two things had to change for the current markup, and the first one is a real
! trap. X now wraps the name row one level deeper than the userstyle assumed:
!
!   row
!    ├─ div.w-10            avatar column
!    └─ div.flex-1          content column
!         ├─ div.gap-0.5    name/handle row
!         │    ├─ div.post-actions   name + handle + time
!         │    └─ div[dir=auto]      ...and, for short posts, the tweet text
!         └─ div.gap-3      media, quote, buttons
!
! The userstyle's "+ div > :first-child" assumes the content column's first
! child IS the name row. It is, but the name row also contains the tweet text
! for short posts, so moving it to column 2 drags the text with it and the text
! stops being full width. So the name row is dissolved too, and only the
! .post-actions block inside it is placed in column 2.
!
! Without this, the grid moves the avatar into its own row and the text never
! regains the width, which is the bug the first draft shipped: measured
! identical to no rule at all.
!
! :matches-path(/home/) replaces the url-prefix scope. The avatar is matched by
! the x-avatar class on the div inside its link, which is X's own hook and is
! not a Tailwind utility.
x.com##article div:matches-path(/home/):has(> div[class*="w-10"] > div > a > div[class*="x-avatar"]):style(display: grid !important; grid-template-columns: 40px minmax(0, 1fr) !important; column-gap: 8px !important; row-gap: 4px !important; align-items: start !important;)

! Avatar: top-left cell.
x.com##article div:matches-path(/home/):has(> div[class*="w-10"] > div > a > div[class*="x-avatar"]) > div[class*="w-10"]:style(grid-column: 1 !important; grid-row: 1 !important; align-self: center !important;)

! The content column dissolves, so its children become grid items.
x.com##article div:matches-path(/home/):has(> div[class*="w-10"] > div > a > div[class*="x-avatar"]) > div[class*="flex-1"]:style(display: contents !important;)

! The name row dissolves as well, so the tweet text inside it can escape to
! full width while the name stays beside the avatar.
x.com##article div:matches-path(/home/):has(> div[class*="w-10"] > div > a > div[class*="x-avatar"]) > div[class*="flex-1"] > div[class*="gap-0.5"]:style(display: contents !important;)

! Name, handle and time: top-right cell, level with the avatar.
x.com##article div:matches-path(/home/):has(> div[class*="w-10"] > div > a > div[class*="x-avatar"]) div[class*="@container/post-actions"]:style(grid-column: 2 !important; grid-row: 1 !important; align-self: center !important; min-width: 0 !important;)

! Tweet text: full width, on its own row under the name.
x.com##article div:matches-path(/home/):has(> div[class*="w-10"] > div > a > div[class*="x-avatar"]) > div[class*="flex-1"] > div[class*="gap-0.5"] > div[dir="auto"]:style(grid-column: 1 / -1 !important; grid-row: 2 !important; min-width: 0 !important;)

! Media, quote cards, buttons: full width too.
x.com##article div:matches-path(/home/):has(> div[class*="w-10"] > div > a > div[class*="x-avatar"]) > div[class*="flex-1"] > :not(div[class*="gap-0.5"]):style(grid-column: 1 / -1 !important; min-width: 0 !important;)

! ---------------------------------------------------------------------------
! 6. DECLUTTER - menu entries the user does not want
! ---------------------------------------------------------------------------
! Your original rules, kept in spirit. The href checks still work because
! those paths are stable; they are the ones that do the real work. The
! :has-text() rules are a backstop for entries that are rendered as buttons
! with no href. :upward(1) lifts the match from the label to its row, which is
! how your original "a:has-text(Calls):upward(1)" worked.
!
! Every procedural rule here ends in ":style(display: none !important)" on
! purpose; without an action the engine emits it as a hide selector and Brave
! then hands ":has-text(...)" to the CSS parser, which rejects it. See the
! note near the top of this file.
!
! If you WANT any of these, delete its lines (or prefix the line with "!").
